## P0：公开推送前必须完成

### 1. 修正桌面授权默认模型

`desktop_auth_service.go` 当前硬编码返回 `gpt-5-codex`，而生产悠米账号当前白名单和成功探测模型不一致。必须改为可配置的生产模型，或从订阅分组允许模型中选择默认值，并完成以下真实验证：

1. 新账号真实购买套餐。
2. 创建全新订阅 Profile。
3. 在 Codex 中发送真实消息。
4. 验证 SSE、工具调用、长上下文与模型计费记录。

只验证“授权完成”和“Profile 创建成功”不足以证明用户可以对话。

### 2. 增加上游容量并限制首发规模

当前只有一条悠米上游账号，审计时余额约 `$8.3`，不足以覆盖一份标准套餐的最坏成本；生产日志已有 `no available accounts`、上游 `503` 和分组 RPM 超限记录。

- 上线前充值到至少能覆盖首批售出套餐的保守成本，不能使用销售额到账后再补上游余额的方式运行。
- 至少增加第二条可用上游路径，验证主线路 5xx/429 时自动切换。
- 首发限制 20–30 名付费用户，或给套餐增加库存/总销量上限；达到阈值自动停售。
- 对“无可用账号”、连续 5xx、上游余额不足和分组 RPM 超限建立可直接触发的告警。

### 3. 补齐付费服务法律与支持入口

当前公开设置中服务条款、使用政策、支持地区和服务特定条款内容为空，登录协议未启用，联系信息与文档地址为空。

- 发布服务条款、隐私政策、退款规则、可接受使用政策、支持地区及上游中断说明。
- 注册和付款前要求用户明确同意，并记录协议版本与时间。
- 配置不公开订单隐私的客服邮箱或工单入口；GitHub Issue 只处理不含订单资料的技术问题。
- 在购买页明确套餐额度、RPM、有效期、退款条件和服务中断处理方式。

### 4. 加固账号与注册安全

当前公开设置中管理员 TOTP、Turnstile、风险控制和密码重置均未启用。

- 管理员启用 TOTP，日常使用普通账号，管理员账号不用于消费或购买。
- 注册、登录、验证码和找回密码接入 Turnstile 或等价的人机校验与速率限制。
- 开启密码重置，并验证邮件链路。
- 对注册、登录、支付创建、桌面授权创建和兑换接口配置 IP/账号级限速。

### 5. 完成异地备份和恢复演练

当前滚动备份与生产数据仍位于同一块 OCI 系统盘，只能防误操作，不能防实例或磁盘整体损坏。

- 每周至少同步一份加密备份到 OCI Object Storage、Cloudflare R2 或另一独立位置。
- 在临时 PostgreSQL/Redis 环境恢复最近备份，核对用户、订单、订阅、设备 Key 和支付配置。
- 记录恢复耗时、镜像摘要和数据库迁移版本，演练成功后才能勾选恢复闭环。

## P1：首发前强烈建议完成

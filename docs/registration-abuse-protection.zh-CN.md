# 注册赠送与邮箱风控

## 当前规则

- 注册接口按公网客户端 IP 限制为每分钟最多 5 次。命中后直接返回 HTTP 429。
- 注册赠送保护按公网客户端 IP 计算，每 24 小时最多允许 3 次赠送名额尝试。
- 第 4 次及之后仍允许创建账号、登录和购买套餐，但不会自动发放注册赠送余额、默认订阅或平台赠送额度。
- 注册赠送名额在请求开始时预占；注册失败会归还名额，避免验证码错误、邮箱冲突等失败请求消耗额度。
- Redis 不可用时仍允许注册，但本次注册不发放赠送额度；注册入口本身仍由独立的每分钟限流保护。
- 邮箱验证码、Turnstile、邮箱重复检查、`+` 别名和 Gmail 点号归一化继续生效。
- 当前没有“同一设备只能注册一个账号”的硬限制。桌面端无法可靠获得稳定设备身份，IP 也可能被公司、校园、家庭网络共享，因此不采用一刀切封禁。

## 邮箱域名黑名单

管理员可在“系统设置 -> 用户注册 -> 临时邮箱域名黑名单”中维护：

- `@mail.tm` 匹配单个域名；
- `*.tempmail.example` 匹配根域名及其子域名；
- 发送验证码和最终注册都会执行黑名单校验。

正常公共邮箱（例如 QQ、Outlook、Gmail）不应加入黑名单，否则会误伤真实用户。建议只加入确认属于一次性邮箱服务的域名，并定期根据注册日志补充。

## 运营建议

如果活动流量继续明显增长，建议把注册赠送从“注册即发”调整为“完成首条有效请求后发”或“注册后 24 小时内完成邮箱验证并通过基础使用检查后发”。当前版本先采用 IP 每日 3 次软限制，便于观察误伤率和转化率。
